# Architecture

## Overview

```
[Browser]
    ↓ HTTPS (Port 443)
[Traefik Proxy]  ← SSL termination (Let's Encrypt), Dynamic Routing
    ↓
┌───────────────────────┐      ┌────────────────────────┐
│  Frontend (Next.js)   │      │   API Gateway (Spring) │
│  app.yourdomain.com   │      │   /api/...             │
└───────────────────────┘      └────────────────────────┘
    ↓                                  ↓
    └──────────────────┬───────────────┘
                       ↓ Internal Docker network (Secured with X-Internal-Token)
┌──────────────────────────────────────────────────────────────────────────┐
│                             Microservices                                │
│  users :8081        finances :8082        banks :8083                    │
│  notifications :8084 upload :8085         investments :8086              │
└──────────────────────────────────────────────────────────────────────────┘
    ↓                        ↓                           ↓
[PostgreSQL :5432]     [Kafka :9093]               [MinIO :9000]
 (Multi-schema)        (Event-Sourcing Hub)        (Object Storage)

      ↖ Scrapes via Actuator         ┌───────────────────┐
       ──────────────────────────────┤ Observability     │
                                     │ Prometheus/Grafana│
                                     └───────────────────┘
```

## Rules

- **Zero Exposure:** No microservice (including Gateway and Frontend) exposes ports to the host in production. Only Traefik (Proxy) and Observability tools (optional) expose ports.
- **S2S Authentication:** All inter-service communication requires a shared secret in the `X-Internal-Token` header.
- **SSL Always:** All external traffic is encrypted via SSL (Auto-generated by Let's Encrypt).
- **Logical Isolation:** Each microservice owns exactly one PostgreSQL schema.
- **Event-Driven Balance:** Financial transactions and bank balance updates are decoupled via Kafka (`transaction.created` topic) for eventual consistency and resilience.
- **Transactional Notifications:** Notification events are only dispatched *after* the database transaction commits (via `@TransactionalEventListener`).


## Authentication & Security

### External (User to Gateway)
Tokens are stored in **HttpOnly cookies** (not localStorage). The browser sends them automatically.

1. Client → Gateway → Users service: `POST /api/v1/auth/login`
2. Users service sets three cookies: `access_token` (HttpOnly), `refresh_token` (HttpOnly), `user_info` (JS readable).
3. Gateway validates JWT and injects `X-User-Id` header downstream.

### Internal (Service to Service)
Internal requests are secured via a shared secret (`INTERNAL_AUTH_TOKEN`). 
- **Gateway:** Injects `X-Internal-Token` into all proxied requests.
- **Feign Clients:** Automatically inject the token via `FeignRequestInterceptor`.
- **Validation:** All services run an `InternalAuthFilter` to reject requests without a valid token.

### CSRF Protection
State-changing requests require a `X-XSRF-TOKEN` header, validated against the `XSRF-TOKEN` cookie.

## Kafka Strategy

| Topic                   | Published by | Consumed by           | Purpose                               |
|-------------------------|--------------|-----------------------|---------------------------------------|
| `transaction.created`   | Finances     | Banks                 | Async balance update (Event Sourcing) |
| `payment.recorded`      | Banks        | Finances              | Confirm transaction recording         |
| `payment.due`           | Finances     | Notifications         | Email/SSE alert                       |
| `user.registered`       | Users        | Notifications         | Welcome email                         |
| `investment.threshold`  | Investments  | Notifications         | Price alert                           |

**Resilience:** All consumers use `ErrorHandlingDeserializer` and a `DeadLetterPublishingRecoverer` to send "poison pills" to `.DLT` topics rather than blocking the partition.

## Observability

The system uses a full Prometheus/Grafana/Loki stack for monitoring.
- **Metrics:** Each service exposes `/actuator/prometheus`. Prometheus scrapes these every 15s.
- **Dashboards:** Grafana (Port 3001) visualizes JVM health, Kafka throughput, and business metrics.
- **Logging:** Promtail forwards container logs to Loki for centralized searching in Grafana.

## Key Decisions

| Decision | Reason |
|---|---|
| Event-Sourced Balance | Fixes "Split-Brain" issues where a transaction is recorded but balance fails to update. |
| S2S Shared Secret | Simple and effective for internal networks where mTLS is overkill. |
| French Amortization | Standardizes loan calculations with fixed monthly installments. |
| PDF Streaming | Prevents OOM (Out of Memory) kills by processing large statements without loading the whole file into RAM. |
| Resilience4j | Protects against external API (IOL) downtime or token expiry. |
| Centralized API Config | Eases frontend deployment across different environments (Dev, Staging, Prod). |
